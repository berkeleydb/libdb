**Gate 6** (the metal benchmark) was not run. The fixes are a macro that changes
which type a load goes through, an argument check on `DB->open`, and the order
of two latches on a file-close path. None of them is on a hot path. **Gate 8**
(the soak) was not run either, because no fix changes resource lifetime.

**L3, which bug reproduces where.** `bamc_prev_alias` fails on the base only on
FreeBSD aarch64. The `__bamc_prev` strict-aliasing reorder happens with clang
`-O2` on aarch64. On x86_64, gcc and clang emit the accesses in source order,
so the test passes on both base and release there, as L3 allows. The other two
fixes reproduce on all three hosts.

## The aarch64 TCL batch, read carefully

The aarch64 TCL batch reported three tests that are not verdicts on the
candidate:

- **`lock003`** (release batch). Two of five `lockscript` children reported
  `BDB0060` / `BDB0061 PANIC`, and their siblings then blocked. I killed the
  stuck children by hand, so the driver's later "PASS" for this run does not
  count. **Rerun:** four alternating isolated runs on base and release, then one
  more each. All PASS, with 0 panics on both. This is the FreeBSD
  process-shared-mutex limitation tracked as B3 in `test/KNOWN-ISSUES.md`
  (`kern.ipc.umtx_vnode_persistent=0` on this host). It is intermittent and not
  specific to the candidate.
- **`dead001`** (release batch): `FAIL: begin.pid not created`. The test
  directory was cleared underneath it by the `lock003` cleanup that ran beside
  it. **Rerun in isolation:** base PASS, release PASS.
- **`fop003`** (release batch): `no_db_handle: expected 0, got 1`. The batch
  leaves a handle open from an earlier test in the same `tclsh`. **Reruns:**
  - run alone, release: PASS;
  - run after `test001`, `test054` and `sdb001` in one `tclsh`, release: PASS;
  - run alone, base: PASS.
- **`test001` crashed the base batch (SIGSEGV).** This is the `__bamc_prev`
  aliasing bug the candidate fixes (#218), reproduced on the base tag. The
  release batch passed `test001`. The same crash took down the base
  "`fop003` after others" rerun.

**Linux and FreeBSD x86_64 ran all 21 TCL tests clean on both base and
release.**

## What the release fixes

| PR | Fix | Who sees it |

| #219 | `DB_TRUNCATE` with a subdatabase name truncated the **whole file**; now `EINVAL` (BDB5384) | any non-locking environment |
| #220 | `__memp_mf_discard` took a file bucket under the mpool allocator latch (a lock-order inversion; a diagnostic build PANICs) | all builds; diagnostic builds abort |
