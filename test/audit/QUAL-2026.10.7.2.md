# v2026.10.7.2 qualification (LTS patch release, 2026-11-03)

gates for an LTS patch release in [`QUALIFICATION-MATRIX.md`](QUALIFICATION-MATRIX.md)
(gates 1–5 and 7, plus L1–L4). Gate 8, the soak, also ran, because the SSI fix
changes how long SIREAD markers live. The candidate was compared with the base

The skips are environmental: no JDK (`u8_backup_config`, `u9_serializable`),
no meson on FreeBSD (`meson_autoconf_parity`), and `mvcc_mtx_doublefree` when
failchk reclaims no mutex, so its scenario is never built.

**† `run_qam_extent_vrfy` on FreeBSD.** The first tier run on both FreeBSD hosts
timed it out (`rc=124` at its 600 s limit). It is I/O-bound by design: about 775
syncs, one per extent file. Run alone on the same hosts it takes 602–640 s, and
the **base tag takes the same time** (x86_64: base 636 s, release 640 s), so the
release did not slow it down. These hosts use their EBS root (UFS with soft
updates), not the instance store the 2026.10.7.1 hosts used. The tier was rerun
with `TIMEOUT=1200` for that one runner, and those are the counts above. The
limit on the line stays at 600 s; GitHub's runners need about 181 s.

**L3, the SSI fix.** The isolation tier fails on the base on every host with
`ssi_multiread_skew` committing the cross-leaf write skew in 40/40 attempts, and
passes on the release. The cycle checker (`CYC_VALPAD=200`, several records per
leaf, 40 seeds, 2 s each) found non-serializable histories on the base on every
host and configuration, and none on the release. No release seed tripped the
throughput floor or the watchdog.

**`ssi_livelock` on FreeBSD prints `BDB3010`.** On both FreeBSD hosts the
release run printed `BDB3010 error getting a page for writing` 30–89 times in
3 s. A probe that counts return codes showed that every transaction that printed
it returned `DB_SNAPSHOT_CONFLICT` or `DB_SNAPSHOT_UNSAFE` and aborted normally,
and none returned another code. `__memp_dirty` suppresses that message for a
deadlock but not for an SSI abort, and the SSI fix raises the abort rate under
contention. The message is noise, not a failure. The fix is #261, for the next
patch release.

**Gate 6** (the metal benchmark) was not run. The SSI change adds a scan of the
page's write holders when a SIREAD marker is granted, which only applies to
`DB_TXN_SERIALIZABLE` transactions. `ssi_livelock` and the cycle checker show
the same commit throughput as the base. The other fixes are on rare paths: a put
over a deleted key, and locker allocation when a stripe runs dry.
