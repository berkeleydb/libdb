# libdb coverage baseline (Tier B3 of the test-suite maturity plan).
# src/-only, gcov/lcov, representative test subset (see test/coverage/README.md).
# The Coverage workflow FAILS (test/coverage/ratchet.sh) if branch coverage drops
# more than branch_tolerance below this.  It used to only warn, on a job that was
# additionally continue-on-error, so a regression was reported by nothing.
# Update after landing new tests that raise coverage (ratchet upward, never down).
#
# THESE NUMBERS COME FROM test/coverage/run_coverage.sh -- the script
# .github/workflows/coverage.yml actually runs -- and from nothing else.
#
# That distinction matters and was previously wrong here.  From commit 1ced5023
# until now this file carried FULL-SUITE figures (48.0/36.1, then 62.3/46.2 for
# report #2, then 68.0/50.2 for report #3).  Those were produced by
# full_run2_par.sh / full_run3_combined.sh / full_run4.sh, which run the ENTIRE
# Tcl suite in parallel (5 access methods x ~135 tests, ~20 subsystem groups, 37
# replication tests).  run_coverage.sh deliberately runs a BOUNDED ~34-test
# curated subset instead.  So the ratchet was comparing a subset measurement
# against a full-suite ceiling it structurally could not reach, which made the
# advisory warning fire unconditionally and hid the real regression signal.
#
# Measured 2026-09-09 on an idle dedicated EC2 c7i.24xlarge (96 vCPU, verified
# load ~0.0), master @ b4d65c25f + the cov_* wiring, gcc/gcov 11.5.0, lcov
# 2.0-1, `--enable-test --enable-faultinject`, -O0 -g --coverage, wall 34m28s.
# Denominator includes dbinc_auto (run_coverage.sh does not strip it; reports
# #2/#3 did, which is a second reason their figures are not comparable).
#
# Full-suite figures live in FULL-COVERAGE-REPORT-{2,3,4}.md, not here.
# ===========================================================================
# RATCHET-VARIANCE -- where branch_tolerance below comes from.  MEASURED.
#
# The tolerance had to be a measured number, not a guess: gcov is deterministic
# for deterministic tests, but this subset is not entirely deterministic (the
# recd group crashes the environment at log-record boundaries, the dead/register
# group spawns worker processes, cov_oom_paths strides fault-injection points).
#
# Measured 2026-09-20 on an idle dedicated 32-vCPU EC2 box, THREE full
# run_coverage.sh runs of the same tree in separate worktrees:
#
#	run   branch hits   of 79867   branch %
#	W1       32271                 40.4059
#	W2       32272                 40.4072
#	W3       32232                 40.3571
#
#	spread (max-min)  0.0501 pp
#	stdev             0.0286 pp
#	wall              1970 / 1970 / 1969 s
#
# branch_tolerance=0.3 is therefore about 10x the observed standard deviation and
# 6x the observed spread: tight enough that a real regression cannot hide inside
# it (the smallest defect-bearing tier in the subset moves far more than 0.3pp --
# losing TestChannel alone moves 3.8), loose enough that it will not fire on
# noise.
#
# FIRST ATTEMPT AT THIS MEASUREMENT GAVE 40.4 / 36.6 / 39.4 -- a 3.8pp spread --
# AND IT WAS NOT NOISE.  Three concurrent runs raced for TestChannel's hard-coded
# repmgr TCP ports (base 30100, test/c/suites/TestChannel.c:1305): one run was
# clean, one took SIGABRT, one reported a CuTest failure, and because TestChannel
# is the only thing in the subset that exercises live replication, 60 files under
# rep/ and repmgr/ swung ~3,100 branches (rep_record.c alone 476 -> 0) while every
# other phase was second-for-second identical.  Fixed by giving each run a private
# BDBPORTRANGE window (test/c/run_cov_cutest.sh); the numbers above are from
# after that fix.  Two sibling collisions were fixed at the same time: global
# `pkill -f 'wrap.tcl'` patterns that killed other runs' workers, and ~15 fixed
# /tmp log paths.  Had the port race not been found, the tolerance would have had
# to be ~4pp, which is wide enough to hide any regression worth gating on.
#
# Re-measure if the test subset changes materially.
# ===========================================================================
line=59.4
branch=40.4
function=78.4
# The gate: test/coverage/ratchet.sh fails when measured branch coverage is
# below branch minus branch_tolerance.  Only BRANCH gates -- line and function
# are reported.  Line coverage flatters: a line executed once with one outcome
# of a two-way branch counts as covered, which is the defect class P1-P5 and U7
# all lived in.
branch_tolerance=0.3
