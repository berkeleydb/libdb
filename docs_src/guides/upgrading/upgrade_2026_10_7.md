## Upgrading to libdb 2026.10.7

**On macOS on Apple Silicon (arm64), libdb 2026.10.7 changes the shared-memory environment region format.** On every other platform, nothing changes: a 2026.10.7 build produces the same region format as 2026.10.6, and environments created by either release attach to the other.

Databases and log files do not change on any platform.

### What changed and why

Since 2026.10.6, FreeBSD and Linux on 64-bit ARM have used a hybrid mutex: a short test-and-set spin, then a sleep on a pthread primitive. Release 2026.10.6 excluded macOS from it, because a stress test produced no result there. The cause turned out to be the test runner, not the mutex. On macOS the runner could not start its test program, because the library's install name took precedence over `-rpath` and stock macOS has no `timeout` command.

With the runner fixed, the hybrid was compared with the pthread mutex on Apple Silicon. Both passed the same correctness tests (mutex stress, the lock-conflict matrix, and the regression runners). The hybrid was as fast or faster in every measured case, never slower, and lock-manager throughput rose by up to 2× at two threads. libdb 2026.10.7 therefore selects the hybrid on macOS/arm64 by default, as it already did on the other arm64 platforms. See `test/bench/F7-MACOS-HYBRID-2026-10.md`.

The hybrid mutex is a different shared structure from the pthread mutex, so the macOS/arm64 environment build signature changes.

### Build signatures

| Platform | 2026.10.6 | 2026.10.7 |
| --- | --- | --- |
| macOS arm64 | `0xe0ad2911` | `0x2c8d3688` |
| Linux / FreeBSD x86_64 (LP64) | unchanged | unchanged |
| FreeBSD / Linux aarch64 | unchanged | unchanged |
| Windows | unchanged | unchanged |

### What you will see on macOS arm64 if you do not follow the procedure

A 2026.10.7 process that opens an environment created by 2026.10.6, or the other way round, fails cleanly:

    BDB1539 Build signature doesn't match environment
    DB_ENV->open: DB_VERSION_MISMATCH

Nothing is read or written in that case. This includes a 2026.10.7 process and a 2026.10.6 utility such as `db_stat` or `db_recover`.

To keep the 2026.10.6 region format on macOS instead, configure with `--with-mutex=POSIX/pthreads/library`.

### Procedure (macOS arm64 only)

1. Shut down every process using the environment, including utilities.
2. Run recovery with the **old** release, or confirm the environment was shut down cleanly.
3. Remove the environment region files (`DB_ENV->remove`, or delete `__db.0*`). Do not remove databases or logs.
4. Install libdb 2026.10.7.
5. Reopen the environment. libdb recreates the region files in the new format.
