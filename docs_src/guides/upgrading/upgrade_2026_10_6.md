## Upgrading to libdb 2026.10.6

**libdb 2026.10.6 changes the shared-memory environment region format.** Databases and log files do not change. Only the region files (`__db.001`, `__db.002`, …, or the equivalent shared memory segments) are affected, and libdb recreates them from scratch whenever an environment is opened after it has been removed.

As with 2026.10.5, this is a deliberate region-format change made in exchange for scalability and portability improvements. No release has been designated long-term support, so the region format is not yet frozen. (Once an LTS release is cut, region changes within that line will not be made.)

### What changed and why

Three groups of changes contribute to this release:

- **Multi-core scalability (RFC 0015).** The transaction-detail records now carry their MVCC mutex across recycling instead of destroying and recreating it on every transaction (S4), the memory-pool put counters moved off the hot cache line (S3), the file-name cache keeps a transaction off `dbp->mutex` on the per-cursor path (M5), and `db_stat` now reports the per-stripe locker-wait and region-latch counts truthfully (S7). On the measured workloads these are correctness-and-overhead improvements, not throughput cliffs; each ships behind a runtime switch so it can be disabled.
- **aarch64 fast mutex.** Earlier releases had no test-and-set mutex implementation for AArch64, so on 64-bit ARM libdb fell back to plain process-shared pthread mutexes. That is both slower and, on FreeBSD, exposed a defect (B3) where a process-shared pthread mutex becomes unusable once its creating process exits — which could strike even a single-threaded program. libdb 2026.10.6 adds an AArch64 test-and-set / hybrid mutex, which fixes B3 in the default build on ARM and removes the need for the `kern.ipc.umtx_vnode_persistent=1` workaround.
- **Opt-in scalability experiment.** A transaction-detail free list (`DB_TXN_FREELIST`, S5) ships **disabled by default**. A metal A/B measured it as throughput-neutral and crash-free, so it is present for experimentation on large machines but is not part of the default behaviour. A second experiment, a split of the environment region latch onto a dedicated transaction latch (M1), was found by the same A/B to both lose throughput and corrupt the region allocator under concurrency; its switch (`DB_TXN_LATCH_SPLIT`) is therefore inert — setting it logs a warning and runs the safe path. See `test/bench/METAL-AB-2026-10.md`.

The new shared-region state changes the environment's build signature.

### What you will see if you do not follow the procedure

A 2026.10.6 process that opens an environment created by an earlier release, or the other way round, fails cleanly:

    BDB1539 Build signature doesn't match environment
    DB_ENV->open: DB_VERSION_MISMATCH

Nothing is read or written in that case. Mixed-version processes can never share one region, including a 2026.10.6 process and an earlier-release utility such as `db_stat` or `db_recover`.

### Build signatures

The build signature is platform-specific. The value changes on every supported platform between 2026.10.5 and 2026.10.6:

| Platform | 2026.10.5 | 2026.10.6 |
| --- | --- | --- |
| Linux / FreeBSD x86_64 (LP64) | `0xe7904e69` | `0x56a06689` |
| FreeBSD aarch64 | `0x3987e259` | `0x56a06689` |

(The aarch64 signature changes additionally because the AArch64 mutex is a different shared structure from the pthread fallback it replaces.)

### Procedure

This is the standard procedure for a release that changes regions but not log or database formats. It is the third case in [Upgrading Berkeley DB installations](upgrade_process.md).

1. Shut down every process using the environment, including utilities.
2. Run recovery with the **old** release, or confirm the environment was shut down cleanly, so no recovery is pending across the format change.
3. Remove the environment region files (`DB_ENV->remove`, or delete `__db.0*`). Databases and logs are untouched and must not be removed.
4. Install libdb 2026.10.6.
5. Reopen the environment. libdb recreates the region files in the new format.
